# Audit RadarPulse — 7 mars 2026

Stack : React/TypeScript (Vite) · Supabase (Auth, DB, Edge Functions Deno) · Stripe

---

## Résumé exécutif

Le codebase est **fonctionnellement viable** pour un MVP basique (landing → checkout → inbox). Il présente cependant **4 blockers critiques** à régler avant tout déploiement avec des utilisateurs réels, ainsi que plusieurs points majeurs de sécurité.

---

## 🔴 CRITIQUES — Blockers production

### 1. Secrets exposés dans le repo

**Fichier** : `apps/web/.env.local` (et potentiellement dans git history)

Les variables suivantes ne doivent jamais être committées :
- `OPENAI_API_KEY` → clé compromise
- `SERVICE_ROLE_KEY` → clé compromise (accès total à la DB)
- `DEV_CALL_KEY` → clé dev partagée

**Action immédiate :**
```bash
# 1. Rotation des clés dans Supabase Dashboard + OpenAI
# 2. Purger le git history
git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch apps/web/.env.local" HEAD
# 3. Ajouter au .gitignore
echo ".env.local" >> .gitignore
```

---

### 2. `ALLOW_DEV_BYPASS` contourne le paywall

**Fichier** : `supabase/functions/opportunities-search/index.ts`

Si la variable `ALLOW_DEV_BYPASS=true` est définie en production, n'importe qui peut accéder à `/inbox` sans subscription active.

**Action :** Vérifier que ce secret est absent ou `false` en production :
```bash
supabase secrets list  # vérifier ALLOW_DEV_BYPASS
```

---

### 3. `submit-access-request` utilise `sbAdmin()` sans `SERVICE_ROLE_KEY`

**Fichier** : `supabase/functions/submit-access-request/index.ts`

La fonction utilise `sbAdmin()` pour l'insert dans `access_requests`, mais `SERVICE_ROLE_KEY` n'est pas défini comme secret Supabase → erreur "Invalid API key" à chaque soumission.

**Options :**
- A) Définir le secret : `supabase secrets set SERVICE_ROLE_KEY=eyJ...`
- B) Réécrire la fonction pour utiliser le client anon (la table a déjà une RLS anon insert)

---

### 4. Emails de notification non fonctionnels

**Fichier** : `supabase/functions/notify-email/index.ts`

`RESEND_API_KEY` n'est pas configuré → aucune notification admin à la soumission d'une demande d'accès ni à la création d'un abonnement Stripe.

**Action :**
```bash
supabase secrets set RESEND_API_KEY=re_...
supabase secrets set NOTIFY_TO=hello@radarpulse.io
supabase secrets set NOTIFY_FROM=noreply@radarpulse.io
```

## 🟠 MAJEURS

### Sécurité

| Problème | Fichier | Correction |
|----------|---------|------------|
| CORS configuré sur `*` — toutes les origines acceptées | `_shared/cors.ts` | Whitelist `radarpulse.io` uniquement |
| `dispatcher` accepte les appels sans authentification | `functions/dispatcher/index.ts` | Ajouter un secret partagé ou IP whitelist |
| `stripe-create-checkout` ne vérifie pas que le JWT est valide avant créer la session | `stripe-create-checkout/index.ts` | Vérifier `sbAdmin.auth.getUser(token)` |
| Pas de rate limiting sur `submit-access-request` | `submit-access-request/index.ts` | Ajouter rate limit (1 req / IP / 5min) |

### Technique

| Problème | Fichier | Correction |
|----------|---------|------------|
| `quality_score` est 0 sur toutes les opportunités si `OPENAI_API_KEY` manque | `functions/worker/index.ts` | Configurer la clé ou désactiver le filtre par défaut |
| Types TypeScript trop permissifs (`any`) | `worker/index.ts`, `opportunities-search/index.ts` | Typer correctement les clients Supabase |
| Message d'erreur en français dans une app italienne | `RequestAccessPage.tsx` ligne 74 | Traduire en italien |
| `SettingsPage.tsx` vide et inutilisable | `App.tsx` | Implémenter ou retirer du routing |

---

## 🟡 MINEURS

- `ThemeMenu.tsx` — sélecteur de thème affiché mais thème unique, peut confondre
- `LandingPage.tsx` — `VITE_SHOW_DEV_APP` expose un lien vers `/inbox` si mal configuré en prod
- `SubscribePage.tsx` — `window.location.href = data.url` sans vérification de domaine Stripe
- Pas de total count dans l'inbox (pagination sans "X résultats sur Y")
- Pas de feedback si l'utilisateur n'est pas authentifié sur `/abbonamento`

---

## ✅ Ce qui fonctionne bien

- **Flux Stripe** : `SubscribePage` → `stripe-create-checkout` → `stripe-webhook` → upsert subscription — pipeline complet et robuste
- **InboxAccessGate** : vérification subscription correcte (status + period_end)
- **RLS** : bien configuré pour les données utilisateur (subscriptions, telegram_profiles, whatsapp_optins)
- **Déduplication** : `fingerprint` UNIQUE en DB — pas de doublons possibles
- **Worker connecteurs** : TED (EU) opérationnel, architecture connecteurs propre
- **Migrations SQL** : ordonnées, versionnées, commentées
