## CRITIQUE (6 bugs)

### BUG-01 · SQL · Fingerprint non-déterministe
**Fichier :** `migrations/20260301110000_fix_opportunity_ai_fingerprint.sql`
La fonction trigger `set_opportunity_ai_fingerprint_from_raw()` utilise `LIMIT 1` sans `ORDER BY`. Résultat : le même `opportunity_ai` peut recevoir des fingerprints différents selon l'ordre d'exécution en base.
**Fix :** Ajouter `ORDER BY o.created_at DESC LIMIT 1`.

---

### BUG-08 · Edge Function · `Math.random()` dans `generateRandomPassword()`
**Fichier :** `functions/verify-magic-link/index.ts`
`Math.random()` n'est pas cryptographiquement sûr. Un attaquant peut potentiellement prédire les mots de passe générés.
**Fix :** Utiliser `crypto.getRandomValues()` (Deno natif) :
```typescript
const buf = new Uint8Array(32);
crypto.getRandomValues(buf);
```

---

### BUG-09 · Edge Function · Énumération utilisateurs via `listUsers()`
**Fichier :** `functions/verify-magic-link/index.ts`
La fonction appelle `listUsers()` puis filtre par email — O(n), vulnérable aux attaques DOS, et révèle indirectement l'existence des utilisateurs.
**Fix :** Utiliser `sbAuth.auth.admin.getUserByEmail(email)` directement.

---

### BUG-14 · Edge Function · TODO non implémenté — email de confirmation
**Fichier :** `functions/submit-access-request/index.ts`
Commentaire `// TODO: notify-email via Resend` jamais implémenté. Les utilisateurs qui soumettent une demande d'accès ne reçoivent aucun email de confirmation.
**Fix :** Implémenter l'appel à `notify-email` ou lever une erreur explicite si `RESEND_API_KEY` manque.

---

### BUG-15 · Edge Function · Injection dans la clause `or()` PostgREST
**Fichier :** `functions/opportunities-search/index.ts`
Le cursor (`cursor.id`, `cursor.published_at`) est injecté directement dans une query string PostgREST sans validation de format UUID/ISO.
**Fix :** Valider UUID avec `/^[0-9a-f]{8}-…$/i` avant utilisation.

---

### BUG-30 · Cross-cutting · Pas de handler d'erreur global dans les Edge Functions
Plusieurs fonctions n'ont pas de `try-catch` global. Une erreur inattendue peut exposer des stacktraces ou laisser le client sans réponse.
**Fix :** Wrapper tous les `Deno.serve()` dans un try-catch global.

## MAJEUR (16 bugs)

### BUG-02 · SQL · Score `completeness_score` — logique documentée mais trompeuse
**Fichier :** `migrations/20260301091000_add_opportunity_quality.sql`
La division par `4.0` est correcte mais non commentée. Si les champs éligibles changent, la formule deviendra silencieusement fausse.
**Fix :** Ajouter un commentaire SQL explicatif sur la formule de normalisation.

---

### BUG-03 · SQL · Cast JSON → boolean dangereux dans la migration `is_deleted`
**Fichier :** `migrations/20260301123000_add_is_deleted_column_and_update_view.sql`
Un cast `::boolean` sur une valeur JSON non standard (`"yes"`, `"1"`) peut interrompre la migration avec une erreur.
**Fix :**
```sql
CASE WHEN (to_jsonb(o)->>'is_deleted') IN ('true','True','1') THEN true ELSE false END
```

---

### BUG-07 · SQL · RLS trop permissive sur `magic_link_tokens`
**Fichier :** `migrations/20260307150000_create_magic_link_tokens.sql`
La policy `anon` permet UPDATE sans condition sur `used = false`, donc un token déjà utilisé pourrait théoriquement être re-consommé si la logique applicative échoue.
**Fix :** Ajouter `USING (NOT used AND expires_at > now())` sur la policy UPDATE.

---

### BUG-10 · Edge Function · L'utilisateur existant perd son mot de passe
**Fichier :** `functions/verify-magic-link/index.ts`
Pour un utilisateur existant, la fonction génère un mot de passe aléatoire et le stocke — sans jamais le communiquer à l'utilisateur. Connexion par mot de passe impossible ensuite.
**Fix :** Pour les users existants, ne pas toucher au mot de passe. Générer une session via `auth.admin.generateLink()`.

---

### BUG-11 · Edge Function · Marquage `used = true` du token en mode fire-and-forget
**Fichier :** `functions/verify-magic-link/index.ts`
Si le UPDATE échoue, l'erreur est seulement loggée (`console.error`). Le token reste utilisable indéfiniment.
**Fix :** Retourner une erreur 500 si le token ne peut pas être marqué `used`.

---

### BUG-12 · Edge Function · Envoi d'email sans await dans `create-magic-link`
**Fichier :** `functions/create-magic-link/index.ts`
Le `fetch()` vers `notify-email` n'est pas `await`-é. Échec silencieux si Resend est down.
**Fix :** Awaiter et vérifier `res.ok`.

---

### BUG-19 · Web · `as any` masquant des bugs de typage dans `App.tsx`
**Fichier :** `apps/web/src/App.tsx`
Plusieurs utilisations de `as any` pour `user_metadata`, `app_metadata`, et l'objet session.
**Fix :** Créer des types `UserMetadata` / `AppMetadata` explicites.

---

### BUG-20 · Web · Race condition sur la vérification du magic link
**Fichier :** `apps/web/src/App.tsx`
Après `setSession()`, le code appelle `init()` une seconde fois. `useAuthUser()` peut déjà avoir déclenché un re-render, créant un état d'auth incohérent.
**Fix :** Éviter le double appel à `init()` après une vérification de magic link réussie.

---

### BUG-22 · Web · Variables d'environnement non validées
**Fichier :** `apps/web/src/lib/env.ts`
`VITE_SUPABASE_URL` et `VITE_SUPABASE_ANON_KEY` ne sont pas validées. Si manquantes, le client Supabase échoue silencieusement plus tard avec des erreurs confuses.
**Fix :** Lever une exception au boot si ces variables sont absentes.

---

### BUG-24 · Web · `readJwt()` sans gestion d'erreur sur session null
**Fichier :** `apps/web/src/features/inbox/useInboxData.ts`
Si `getSession()` retourne null, un JWT vide `""` est envoyé au serveur — retour 401 sans message utile pour l'UI.
**Fix :** Lancer une erreur explicite si `session?.access_token` est null.

---

### BUG-27 · Config · Mot de passe minimum trop court
**Fichier :** `supabase/config.toml`
`minimum_password_length = 6` — insuffisant pour 2026.
**Fix :** Passer à `12`.

---

### BUG-28 · Config · `verify_jwt = false` sur les fonctions worker/dispatcher
**Fichier :** `supabase/config.toml`
Ces fonctions sont publiquement appelables par n'importe qui sans authentification.
**Fix :** Activer `verify_jwt = true` sauf si intentionnellement public, et documenter le choix.

---

### BUG-31 · Cross-cutting · Pas de validation d'entrée cohérente entre Edge Functions
Chaque fonction implémente sa propre validation (ou pas). Risque d'incohérences et de failles.
**Fix :** Créer `_shared/validation.ts` avec `validateEmail()`, `validateUUID()`, `validateISODate()`.

---

### BUG-32 · Cross-cutting · Logging non structuré
`console.log()` / `console.error()` partout sans contexte (function name, request ID, user ID).
**Fix :** Utiliser un logger minimal structuré : `{ level, fn, msg, ...context }`.

---

### BUG-17 · Edge Function · Pas de retry sur l'envoi Resend
**Fichier :** `functions/notify-email/index.ts`
Si Resend est temporairement indisponible, l'email est perdu sans retry.
**Fix :** Implémenter un retry simple (2-3 tentatives) avec backoff.
